# 实现计划（审阅稿）: Nobody 下一阶段重构与系统扩展

## 概述

本计划用于把 Nobody 从“可玩剧情原型”升级为“规则驱动 + LLM增强”的修仙模拟器。
核心目标：

1. 修复剧情系统重复、失真和推进体验问题。
2. 建立可解释且非纯数值比大小的战斗/战力判定体系。
3. 增加功法系统、地图系统、角色系统，并与剧情系统深度联动。
4. 明确 LLM 职责：负责结构化内容生成与填充，不负责长期记忆；长期状态由游戏引擎持久化。
5. 提升剧情文本的“厚度”和“可读性张力”，让推进过程更具沉浸感与文学性。

## 设计原则

- 规则优先：关键世界逻辑由引擎规则约束，LLM 只在规则边界内生成内容。
- 结构化优先：LLM 输出 JSON（或严格 schema），再进入验证器。
- 可解释优先：每次战斗结果、剧情约束命中，都能给出“为何如此”的解释片段。
- 状态单一来源：角色/功法/装备/地图/关系全部落库到游戏状态，不依赖 LLM 记忆。
- 混合记忆优先：LLM 采用“有界上下文窗口 + 外置记忆检索”协同，历史一致性由“存储 + 检索 + 校验”体系保证。
- 渐进重构：先建立领域模型与判定引擎，再逐步替换现有剧情推进链路。

- [x] 1. 建立“剧情一致性问题清单”和复现实例库

- [x] 2. 领域模型重构方案设计
  - 梳理并冻结核心实体：Character / Technique / Equipment / Realm / MapNode / Encounter / CombatContext
  - 定义跨模块不变量（例如“大境界压制不可被低阶法器无条件逆转”）
  - 输出 `docs/architecture/domain-model-v2.md`
  - _验收: 形成字段级 schema 与生命周期说明_

- [x] 3. 数据迁移与兼容策略
  - 设计旧存档到新 schema 的迁移器

  - _验收: 旧存档加载成功率 >= 95%，失败可回退并提示_

### 阶段 B: 剧情系统强化（先修可玩性）

- [x] 4. 引入剧情状态机（Plot State Machine）
  - 明确状态：AutoAdvance / WaitingForChoice / WaitingForFreeText / Resolving / Cooldown
  - 修复“无需输入”连点问题：支持自动推进直到真正进入玩家交互态
  - _验收: 不再出现“无选项且无法推进”的死锁状态_

- [x] 5. 增加剧情去重与记忆检索层
  - 建立“近期事件指纹”与“语义重复检测”
  - 在生成前注入“禁重复约束”
  - _验收: 连续 30 回合重复剧情率显著下降（目标 < 10%）_

- [x] 6. 章节目标驱动生成
  - 每章定义目标：冲突、成长、资源变化、关系变化、伏笔
  - 每次推进必须至少命中其中 1 项，否则触发重生成
  - _验收: 章节推进具有可见变化，不再原地打转_

- [x] 7. 剧情一致性验证器 V2
  - 检查境界、角色关系、地图位置、资源前后因果
  - 对不一致输出进行自动修正或回退
  - _验收: 关键硬约束违例率 < 2%_

- [ ] 7A. 剧情描写厚度与叙事张力增强
  - 建立“叙事片段模板库”：环境、感官、心理、动作、因果余波五类片段
  - 为每次剧情推进增加最小叙事覆盖要求（例如：至少命中环境/动作/心理中的两类）
  - 引入“章节节奏控制”：铺垫 -> 冲突 -> 转折 -> 回落，避免全程平铺直叙
  - 增加“角色内在状态显化”规则（动机、犹疑、执念），避免只报事件不写人物
  - 对生成文本做“空洞表达检测”（模板化套话、重复句式、信息密度过低）并触发重写
  - _验收: 主观评测中“引人入胜”评分明显提升，且长段落信息密度稳定_

### 阶段 C: 角色系统（成长可见化）

  - _验收: 成长有收益也有代价，且可追踪_

### 阶段 E: 地图系统（空间约束）

  - 地图节点：宗门、秘境、城镇、禁地、妖域

- [ ] 13. 移动与遭遇机制
  - 引入路径、时间消耗、遭遇池、区域事件

  - _验收: 不再出现“跨图瞬时冲突”类违和事件_

### 阶段 F: 战斗系统（非单数值比较）

- [ ] 14. 战斗判定引擎 V2（规则矩阵）
  - 判定输入：境界层级、功法标签、武器类别、人格倾向、地形环境、临场状态
  - 判定流程：
    1) 硬约束筛选（如大境界压制、法器可用条件）
    2) 克制矩阵匹配（功法/兵器/环境）
    3) 行为策略匹配（谨慎、嗜战、诈败、保命）
    4) 结果采样与解释生成
  - _验收: 不再出现“高境界反被低阶杂兵压制”的低级违和剧情_

- [ ] 15. 战斗结果解释器
  - 每场战斗输出“主导因素”与“反转因素”文本摘要
  - 将解释写入事件日志供小说生成与复盘
  - _验收: 玩家可理解胜负原因，而非黑盒结果_

- [ ] 16. 战斗与剧情耦合
  - 战斗后状态（伤势、消耗、威望、仇恨）直接影响后续剧情
  - _验收: 战斗不再是孤立事件_

### 阶段 G: LLM 结构化填充与存储策略

- [x] 17. 定义 LLM 输出契约（JSON Schema）
  - 场景生成、选项生成、角色补全、功法描述、遭遇描述分别定义 schema
  - 新增实体 schema：`TechniqueDef`、`CharacterProfile`、`MapNodeDef`、`ItemDef`
  - 字段级约束：命名规范、枚举值、取值范围、缺省策略、版本号
  - _验收: 非 schema 输出全部拒收并进入重试/回退_

- [x] 18. LLM-Engine 协作协议
  - LLM 只生成“建议内容”和“候选结构”，最终落地由规则引擎裁决
  - 明确职责分层：
    - LLM：生成名称与描述（功法名/角色名/地图名等）+ 候选属性
    - Validator：校验 schema、数值与世界约束
    - Engine：根据规则决定最终结果并写入状态
  - 长期信息统一写入 GameState（Rust 端），禁止依赖 LLM 长期记忆
  - 每次生成前必须进行上下文检索拼装（而非依赖历史对话 token）
  - _验收: 断网后读取存档仍可恢复核心世界状态_

- [x] 19. 合理性控制算法
  - 增加“冲突检测 + 局部修正 + 保底模板”三层机制
  - 对高风险输出（境界冲突、地图冲突、人物设定冲突）自动降级
  - _验收: 高风险错配显著减少且可追溯_

- [x] 19A. 实体结构化填充与持久化管线（核心）
  - 实现流水线：`LLM 生成候选 -> Schema 校验 -> 规则裁决 -> 落库 -> 索引 -> 查询`
  - 首批落地实体：
    - 功法：名称、类型、属性、数值、描述、修炼条件、风险标签
    - 角色：名称、身份、境界、人格标签、关系图节点
    - 地图：名称、区域类型、危险度、资源标签、连通关系
  - 存储策略：
    - 结构化实体入本地存储（建议 sqlite/rocksdb 或现有存档结构增强）
    - 按 `world_id / run_id / entity_id` 组织，支持版本化与回滚
    - 提供查询接口：按剧情上下文检索实体并拼接到提示词
  - _验收: LLM 无需记忆历史实体，剧情仍能稳定引用既有功法/角色/地图信息_

- [x] 19B. 数值系统校验层（LLM 输出合理性守门）
  - 建立数值合法区间与关系约束：
    - 同境界功法强度区间
    - 不同境界跨阶上限
    - 法器/功法/角色适配阈值
    - 地图危险度与可遭遇敌阶约束
  - 增加“数值冲突分类器”：
    - 轻微偏离：自动归一化修正
    - 严重冲突：拒收并触发重生成
  - 战力判定采用“标签+规则+上下文”综合，不退化为单一数值比大小
  - 输出审计日志：记录原始值、修正值、触发规则、最终裁决原因
  - _验收: 数值错配剧情（如高境界惧怕低阶杂兵）显著减少并可追溯_

- [x] 19C. 分层记忆与上下文窗口协同体系（核心）
  - 建立三层记忆模型：
    - 短期记忆：最近 N 回合详细事件（高时效）
    - 中期记忆：章节摘要与阶段目标（中等粒度）
    - 长期记忆：世界事实库（角色设定、功法定义、地图事实、重大事件）
  - 实现检索构建器（Context Builder）：
    - 输入：当前场景、参与角色、当前位置、玩家意图
    - 输出：受 token 预算约束的“最相关事实包”
  - 引入“上下文窗口”：
    - 保留最近若干段原始剧情/对话作为短窗口输入
    - 与外置检索事实做去重与冲突裁决，避免信息打架
  - 实现事实优先级策略：
    - 世界硬事实 > 当前章节关键事实 > 最近事件细节 > 文风补充信息
  - 实现一致性回写：
    - LLM 输出被裁决后写回对应记忆层，形成可追踪链路
  - _验收: 长局游玩后剧情首尾可对齐，关键设定不丢失且不自相矛盾_

## 验收指标定义（量化）

- `剧情重复率`
  - 定义：`重复事件数 / 总事件数`（滑动窗口 30 回合）
  - 目标：`< 10%`
- `硬约束违例率`
  - 定义：被一致性校验器判定为硬冲突的输出占比
  - 目标：`< 2%`
- `导出事实覆盖率`
  - 定义：导出文本中可映射回事件日志的句段占比
  - 目标：`>= 98%`
- `上下文命中率`
  - 定义：被采用的上下文事实条目 / 检索返回条目
  - 目标：稳定收敛（避免无效上下文堆积）
- `章节闭环率`
  - 定义：可被判定“完整起承转合”的章节占比
  - 目标：持续提升并在灰度期达到可用标准

## 非目标范围（V2 不做）

- 不做多人在线联机同步。
- 不做开放式 Mod API 大规模重构（沿用现有能力，后置）。
- 不做“仅依赖全文长上下文”式 LLM 记忆方案（坚持混合记忆架构）。
- 不在 V2 首版引入复杂实时战斗 UI（先完成规则与叙事闭环）。

## 回退与兜底策略

- 当 LLM 连续生成失败时，系统自动切换保底模板并继续游戏流程。
- 当数值守门判定为严重冲突时，拒收并记录审计日志，不污染主状态。
- 当上下文检索失败时，至少回落到“长期硬事实 + 最近事件摘要”最小包。
- 当章节自动闭合失败时，允许人工阈值触发，确保不阻塞推进。
