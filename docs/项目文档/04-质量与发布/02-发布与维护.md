# 发布与维护

## 1. 发布目标

发布流程的目标不是“尽快出包”，而是确保：

- 构建稳定
- 主路径可用
- `NoName` 不会因实验功能破坏基础游玩闭环

## 2. 发布前至少确认

- 前端构建通过
- 后端 `NoName` 定向测试通过
- 主游戏闭环能完成一次完整游玩流程
- 存档、加载、脚本加载可正常工作
- `NoName` 调试入口在开发模式下可访问

## 3. 发布关注点

### 引擎层

- 剧情推进是否稳定
- 状态更新是否正确
- 存档兼容是否受影响

### NoName 层

- trace 是否还能生成
- controlled output review 是否仍能显示
- reviewed apply 是否保持显式、可追踪、可拒绝

### 前端层

- 信息中心是否可打开
- 调试台是否渲染正常
- Web mock 与 Tauri 行为是否仍保持一致预期

## 4. 维护规则

- 任何影响 `NoName` 权限边界的修改都必须先更新架构文档
- 任何影响协作边界的修改都必须先更新协作任务清单
- 任何显著改变测试入口的修改都必须同步更新测试文档
