# 系统架构总览

## 1. 总体原则

`Nobody` 当前采用的是“前端交互壳 + Rust 游戏引擎 + 受控 Agent 增强”的分层结构。

核心原则有三条：

- 状态优先：世界状态、剧情状态、存档状态由后端维护
- 规则优先：护栏、规则检查和可回退能力优先于生成自由度
- Trace 优先：关键决策过程可记录、可查看、可追溯

## 2. 分层结构

## 2.1 前端层

主要目录：

- `src/components/`
- `src/stores/`
- `src/platform/`
- `src/types/`

职责：

- 呈现剧情与系统信息
- 承载用户交互
- 管理调试态与 trace 可视化
- 在 Web mock 和 Tauri runtime 之间做适配

## 2.2 命令与运行层

主要入口：

- `src-tauri/src/tauri_commands.rs`
- `src/platform/webRuntime.ts`

职责：

- 向前端暴露统一命令
- 把界面操作转成后端状态操作
- 在开发环境提供 Web mock

当前风险：

- `tauri_commands.rs` 已经很大，后续应继续把复杂逻辑下沉到独立模块
- `webRuntime.ts` 需要持续与后端行为对齐，否则会出现前后端语义漂移

## 2.3 领域与引擎层

主要模块：

- `game_engine`
- `game_state`
- `plot_engine`
- `entity_store`
- `memory_*`

职责：

- 维护剧情状态与章节推进
- 维护世界实体与关系
- 维护剧情历史、记忆、导出与一致性数据

## 2.4 NoName 子系统

主要模块：

- `noname_runtime`
- `noname_trace`
- `noname_guardrails`
- `noname_context_builder`
- `noname_memory_*`
- `noname_output_interface`
- `noname_apply`

职责：

- 生成结构化 proposal
- 构建上下文与记忆召回
- 执行 apply preflight、controlled output review、second guardrail
- 产出 trace，支持人工 review 和显式 apply

## 3. 当前架构结论

- 引擎层已经是稳定的项目基础
- `NoName` 已经嵌入主循环，但仍处于“受控增强”而非“高权重接管”
- 当前最合理的方向是继续降低命令层耦合、统一 mock 与后端语义，而不是直接扩大 Agent 权限
