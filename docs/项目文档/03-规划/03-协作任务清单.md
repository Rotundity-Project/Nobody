# 协作任务清单

## 1. 协作原则

当前项目不适合让协作者直接切入最重的主线编排文件。  
协作应遵循三个原则：

- 优先低耦合任务
- 优先可单测的独立模块
- 优先小步可合并的 PR

## 2. 默认不建议直接碰的文件

- `src-tauri/src/tauri_commands.rs`
- `src-tauri/src/noname_runtime.rs`
- `src-tauri/src/noname_trace.rs`
- `src/platform/webRuntime.ts`
- `src/stores/gameStore.ts`
- `src/types/game.ts`

如果任务必须改这些文件：

- 先在独立模块完成主体逻辑
- 对主线文件只保留最小接线修改
- 合并前单独做 review

## 3. 适合当前主开发者优先处理的任务

### 主线任务 A

- `webRuntime` 与后端语义对齐
- `tauri_commands.rs` 到 `noname_apply.rs` 的继续抽离
- `reviewed apply` 链路继续收口

这些任务与当前主链强耦合，适合由熟悉现状的人继续推进。

## 4. 适合协作者并行处理的任务

### 协作任务 1：检索质量增强

- 目录范围：
  - `src-tauri/src/noname_memory_retrieval.rs`
  - `src-tauri/src/noname_memory_store.rs`
- 目标：
  - 提升排序质量与解释性
  - 不改主链 apply 编排

### 协作任务 2：Structured Notes 生命周期增强

- 目录范围：
  - `src-tauri/src/noname_note_store.rs`
  - `src-tauri/src/noname_memory_types.rs`
  - `src-tauri/src/noname_memory_manager.rs`
- 目标：
  - 完成 active / resolved / archived 的清晰流转
  - 与 compaction/retrieval 接口对齐

### 协作任务 3：角色上下文质量优化

- 目录范围：
  - `src-tauri/src/noname_context_builder.rs`
  - `src-tauri/src/noname_context_types.rs`
- 目标：
  - 提高不同角色的上下文差异度
  - 不改 runtime 主流程

### 协作任务 4：调试与可视化增强

- 目录范围：
  - `src/components/NoNameDebugConsole.vue`
  - `src/components/AgentTracePanel.vue`
  - 对应测试文件
- 目标：
  - 提升 trace 可读性
  - 增强 review / apply 生命周期展示

## 5. 当前不再适用的旧任务分法

旧版 `A1/A2/A3/B2/B3` 等卡片里有多项已不再是“未开始”。  
以后分配任务前，应先核对当前 `main` 的真实代码状态，而不是直接复用旧卡片标题。

## 6. 协作交付要求

- 每个 PR 只解决一个明确问题
- 必须附最小验证命令
- 如果涉及 `NoName`，优先补对应单测
- 不允许为了赶进度直接扩大 `NoName` 权限边界

更细的两周内并行安排，见 [未来两周开发排期](./04-未来两周开发排期.md)。
