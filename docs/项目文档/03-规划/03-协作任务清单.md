# 协作任务清单

## 1. 协作原则

当前项目不适合让协作者直接切入最重的主线编排文件。  
协作应遵循三个原则：

- 优先低耦合任务
- 优先可单测的独立模块
- 优先小步可合并的 PR

## 2. 默认不建议直接碰的文件

- `src-tauri/src/tauri_commands.rs`
- `src-tauri/src/noname_runtime.rs`
- `src-tauri/src/noname_trace.rs`
- `src/platform/webRuntime.ts`
- `src/stores/gameStore.ts`
- `src/types/game.ts`

如果任务必须改这些文件：

- 先在独立模块完成主体逻辑
- 对主线文件只保留最小接线修改
- 合并前单独做 review

## 3. 适合当前主开发者优先处理的任务

### 主线任务 A

- `webRuntime` 与后端语义对齐
- `tauri_commands.rs` 到 `noname_apply.rs` 的继续抽离
- `reviewed apply` 链路继续收口

这些任务与当前主链强耦合，适合由熟悉现状的人继续推进。

## 4. 适合协作者并行处理的任务

### 协作任务 1：检索质量增强

- 目录范围：
  - `src-tauri/src/noname_memory_retrieval.rs`
  - `src-tauri/src/noname_memory_store.rs`
- 目标：
  - 提升排序质量与解释性
  - 不改主链 apply 编排

当前状态：

- 第一轮已完成
- 检索层已能返回排序解释报告，明确展示 `relevance -> recency -> importance` 的排序依据
- store 层已提供 explainable retrieval 代理方法
- 当前仍保持低耦合边界，未修改 `noname_runtime.rs`、`context_builder` 或 apply 主链

### 协作任务 2：Structured Notes 生命周期增强

- 目录范围：
  - `src-tauri/src/noname_note_store.rs`
  - `src-tauri/src/noname_memory_types.rs`
  - `src-tauri/src/noname_memory_manager.rs`
- 目标：
  - 完成 active / resolved / archived 的清晰流转
  - 与 compaction/retrieval 接口对齐

当前状态：

- 第一轮已完成
- notes 状态流转已集中到可复用 lifecycle action，避免调用方直接散写状态
- `archived` 已被定义为终态，不允许 reopen，降低历史 notes 被误激活的风险
- manager 层已在 lifecycle action 后同步 narrative memory store，保证后续 retrieval/context builder 能读到一致状态
- 与 compaction/retrieval 的深度串联仍留到 B4

### 协作任务 3：角色上下文质量优化

- 目录范围：
  - `src-tauri/src/noname_context_builder.rs`
  - `src-tauri/src/noname_context_types.rs`
- 目标：
  - 提高不同角色的上下文差异度
  - 不改 runtime 主流程

当前状态：

- 第一轮已完成
- role context 的 `source_stats` 已显式加入角色优先级标记，便于调试和测试区分不同角色的上下文偏好
- `visible_constraints` 已补充 primary context bias 文案
- 未修改 runtime 主流程，也未增加新的 role 运行模式

### 协作任务 4：调试与可视化增强

- 目录范围：
  - `src/components/NoNameDebugConsole.vue`
  - `src/components/AgentTracePanel.vue`
  - 对应测试文件
- 目标：
  - 提升 trace 可读性
  - 增强 review / apply 生命周期展示

当前状态：

- 第一轮已完成
- trace 面板已新增前置快读条，便于快速核对 proposal / review / human review / apply / guardrail 概览
- 调试台复制摘要已补充 `Trace Breakdown`
- reviewed apply 生命周期展示已补充 `Human Review -> Second Guardrail -> Manual Apply` 顺序核对
- 未新增后端协议字段，仍只消费现有 trace 数据

### 协作任务 5：检索与 notes 串联增强

- 目录范围：
  - `src-tauri/src/noname_memory_manager.rs`
  - `src-tauri/src/noname_note_store.rs`
  - `src-tauri/src/noname_memory_retrieval.rs`
- 目标：
  - 让 active structured notes 能作为检索上下文桥接，提升相关记忆召回
  - 保持 archived notes 不参与召回扩展

当前状态：

- 第一轮已完成
- manager 层已提供 note-aware retrieval 报告，包含召回结果、note contexts 与 explanations
- 已有测试证明 active notes 会扩大相关 episodic 召回，archived notes 不会扩大召回
- 第二轮已完成：context builder 已消费 note-aware retrieval，让 active notes 扩展出的召回结果进入角色上下文包
- `source_stats` 已加入 `noteContext` 统计，便于后续调试上下文来源
- 第三轮已完成：manager 层已提供章节 compaction 桥接入口，可从当前 store 自动收集同章 events 与 active / resolved notes，并默认跳过 archived notes
- 当前没有修改前端、protocol 或 runtime 主链

## 5. 当前不再适用的旧任务分法

旧版 `A1/A2/A3/B2/B3` 等卡片里有多项已不再是“未开始”。  
以后分配任务前，应先核对当前 `main` 的真实代码状态，而不是直接复用旧卡片标题。

## 6. 协作交付要求

- 每个 PR 只解决一个明确问题
- 必须附最小验证命令
- 如果涉及 `NoName`，优先补对应单测
- 不允许为了赶进度直接扩大 `NoName` 权限边界

更细的两周内并行安排，见 [未来两周开发排期](./04-未来两周开发排期.md)。
