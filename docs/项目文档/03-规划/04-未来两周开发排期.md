# 未来两周开发排期

更新时间：2026-04-20  
适用范围：当前 `main` 分支  
排期目标：在不扩大 `NoName` 权限边界的前提下，完成主链收口、协作提效与文档稳定化

## 1. 排期原则

本排期按两条线并行推进：

- 主开发线：处理高耦合、主链、语义一致性问题
- 协作者线：处理低耦合、可独立验证、可小步合并的问题

所有任务都遵循以下规则：

- 任务尽量小，一次只解决一个明确问题
- 每个任务必须有可交付结果和最小验证命令
- 每个任务必须说明禁止触碰的红线
- 每次合并前都要同步文档，不允许“代码变了，文档下次再说”

## 2. 统一红线

两周内默认禁止：

- 直接让 `NoName` 写入最终剧情状态或世界硬事实
- 把新的复杂编排继续堆进 `src-tauri/src/tauri_commands.rs`
- 基于旧卡片标题直接开工而不先核对当前 `main`
- 在没有测试和 trace 证据的情况下调整 `reviewed apply` 权限边界
- 为了省事同时大改主链文件和协作者任务文件

## 3. 文档管理规则

### 正式文档更新位置

- 统一写入 `docs/项目文档/`
- 任务状态变更至少同步更新：
  - [现状评估](./01-现状评估.md)
  - [后续路线图](./02-后续路线图.md)
  - [协作任务清单](./03-协作任务清单.md)

### 文档更新时机

- 开始任务前：确认任务是否还有效
- 任务完成后：更新状态、交付物、验证方式
- 任务被搁置或拆分时：补一条“当前停在哪、下一步由谁接”

### 文档命名规则

- 使用中文
- 文件名采用 `序号-主题名.md`
- 以“当前基线”表达，不再保留旧版 `v1/v2/blueprint/checklist/card` 风格命名

## 6. 交接模板
