# 后续路线图

## 1. 方向原则

后续开发按四个层次推进：

1. 工程收口
2. 主链减压
3. 记忆与上下文增益
4. 更高一层受控输出探索

## 2. 近期优先级

## P0：立即处理

### 任务 1：修复测试环境污染

- 目标：避免 `.review/` 等工作树影响前端测试发现
- 产出：
  - 清理本地工作树或在测试配置中显式排除
  - 在测试文档中补充说明

当前状态：

- 第一轮已完成
- `vitest.config.ts` 已将前端测试发现范围限制在 `src/`，并显式排除 `.review/`
- `npm run test:web-core` 与前端 NoName 定向测试已恢复只命中当前仓库测试文件
- 测试文档与运行文档已补充这一基线说明

### 任务 2：重建正式文档基线

- 目标：用当前中文文档替代旧版漂移文档
- 产出：
  - 新文档目录
  - 统一阅读入口
  - 旧文档移除

## P1：一周内优先完成

### 任务 3：对齐 `webRuntime` 与后端 `NoName` 语义

- 重点：
  - `controlled output review`
  - `policy forbidden scopes`
  - `reviewed apply` 相关返回结构

当前状态：

- 第一轮已完成
- 已补齐 `policy forbidden scopes`
- 已收紧 review 对 proposal 的精确绑定
- 后续继续关注新增 trace / review / apply 字段的同步

### 任务 4：继续从 `tauri_commands.rs` 抽离 `NoName` 编排

- 重点：
  - reviewed apply request 构造
  - review / second guardrail / manual apply 共用逻辑
  - 尽量让命令层只做参数接收与结果返回

当前状态：

- 已完成第五轮下沉
- reviewed apply 的 request builder 与 plotText manual apply helper 已进入 `noname_apply.rs`
- `tauri_commands.rs` 在 reviewed apply 路径上已减少内联快照构造与包装逻辑
- reviewed apply 命令已开始复用共享的 trace 读取、plot state 更新和 trace 回写壳层
- human review intent、人工复核结果写回与 second guardrail 预校验 / 决策记录已进入 `noname_apply.rs`
- `apply_noname_reviewed_output` 的 request input 组装已回收到 `noname_apply.rs`
- 本轮后 A2/A3 可视为阶段性完成；下一步若继续减压，应优先评估低风险 apply 或剧情生成主链中仍重复的编排，而不是扩大新的 apply scope

## P2：收口后继续推进

### 任务 5：增强记忆检索质量

- 重点：
  - 排序可解释性
  - 角色差异化权重
  - 与 narrative notes 联动

当前状态：

- 排序可解释性第一轮已完成
- 检索结果可附带 `NoNameRetrievedMemoryReport`，用于解释每条结果的匹配分、角色加权、时间新近度和重要性
- 角色差异化权重已在解释结果中显式暴露
- 与 narrative notes 的深度联动尚未开始，后续归入 B4

### 任务 6：增强 structured notes 生命周期

- 重点：
  - active / resolved / archived 的推进规则
  - 章节收束时的 note 归档
  - 与 compaction、retrieval、context builder 贯通

当前状态：

- notes 生命周期第一轮已完成
- `active / resolved / archived` 的合法流转已集中为可复用规则
- `NoNameMemoryManager` 已保证 note 状态变化后同步 retrieval store
- 章节收束时 resolved 自动归档的既有行为已保留
- 与 retrieval 的第一轮串联已完成：active notes 可作为检索上下文桥，archived notes 不参与扩展召回
- 与 context builder 的串联已完成第一轮：角色上下文构建会消费 note-aware retrieval，并在 `source_stats` 中暴露 `noteContext`
- 与 compaction 的第一轮串联已完成：`NoNameMemoryManager` 已集中构造章节压缩输入，当前章节 events 与非归档、非 summary notes 会进入 compaction，旧的 chapter summary 不会被重复压缩
- 与章节收束顺序的第一轮串联已完成：`close_chapter_memory` 已固定“先 compact，再 organize/archive resolved notes，最后 upsert summary”
- 与更高层 runtime 编排的更深层串联尚未完成，后续继续推进

### 任务 6.5：优化角色上下文差异度

当前状态：

- 第一轮已完成
- role context 已通过 source priority stats 和 primary context bias 说明强化 `Director / WorldCurator / NpcIntent` 的差异
- 当前改动不影响 runtime 主流程，仍属于低耦合 context builder 层增强

### 任务 6.6：优化调试台可读性

当前状态：

- 第一轮已完成
- trace 面板已提供 `Trace 快读` 条，调试台复制摘要已提供 `Trace Breakdown`
- 当前改动不增加后端协议字段，仅重组现有 trace 信息

### 任务 6.7：收口 reviewed apply 生命周期展示

当前状态：

- 第一轮已完成
- trace 面板、调试台复制摘要和 store 诊断均已展示 `Human Review -> Second Guardrail -> Manual Apply` 顺序核对
- 当前改动不增加后端命令，也不扩大 apply scope

## P3：中期探索

### 任务 7：推进下一层安全输出接口

- 前提：
  - 主链减压完成
  - mock/后端语义一致
  - reviewed apply 结构稳定

当前状态：

- 第一轮评估已完成
- 当前只建议试点非最终状态的 pending / draft / diagnostics-like 输出层
- 不建议直接试点最终剧情、世界硬事实、NPC 隐藏意图或绕过 reviewed apply 的自动写入
- 安全输出草稿层第一轮探针已完成：`NoNameSafeOutputDraft` 只读推导 `drafted / reviewed / guardrailAllowed / manuallyApplied / blocked / fallback`，并固定 `finalPlotStateWriteAllowed=false`
- 评估文档见 [下一层安全输出接口试点评估](./05-下一层安全输出接口试点评估.md)

### 任务 8：评估多角色协作与更强知识检索

- 前提：
  - 当前 `Director + WorldCurator + NpcIntent` 路径稳定
  - 记忆与 protocol 层已具备明确接入点

## 3. 不建议现在就做的事
