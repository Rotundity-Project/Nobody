# 后续路线图

## 1. 方向原则

后续开发按四个层次推进：

1. 工程收口
2. 主链减压
3. 记忆与上下文增益
4. 更高一层受控输出探索

## 2. 近期优先级

## P0：立即处理

### 任务 1：修复测试环境污染

- 目标：避免 `.review/` 等工作树影响前端测试发现
- 产出：
  - 清理本地工作树或在测试配置中显式排除
  - 在测试文档中补充说明

### 任务 2：重建正式文档基线

- 目标：用当前中文文档替代旧版漂移文档
- 产出：
  - 新文档目录
  - 统一阅读入口
  - 旧文档移除

## P1：一周内优先完成

### 任务 3：对齐 `webRuntime` 与后端 `NoName` 语义

- 重点：
  - `controlled output review`
  - `policy forbidden scopes`
  - `reviewed apply` 相关返回结构

当前状态：

- 第一轮已完成
- 已补齐 `policy forbidden scopes`
- 已收紧 review 对 proposal 的精确绑定
- 后续继续关注新增 trace / review / apply 字段的同步

### 任务 4：继续从 `tauri_commands.rs` 抽离 `NoName` 编排

- 重点：
  - reviewed apply request 构造
  - review / second guardrail / manual apply 共用逻辑
  - 尽量让命令层只做参数接收与结果返回

当前状态：

- 已完成第三轮下沉
- reviewed apply 的 request builder 与 plotText manual apply helper 已进入 `noname_apply.rs`
- `tauri_commands.rs` 在 reviewed apply 路径上已减少内联快照构造与包装逻辑
- reviewed apply 命令已开始复用共享的 trace 读取、plot state 更新和 trace 回写壳层
- human review intent 与 second guardrail 决策记录已进入 `noname_apply.rs`
- 下一步若继续减压，应优先评估低风险 apply 或剧情生成主链中仍重复的编排，而不是扩大新的 apply scope

## P2：收口后继续推进

### 任务 5：增强记忆检索质量

- 重点：
  - 排序可解释性
  - 角色差异化权重
  - 与 narrative notes 联动

### 任务 6：增强 structured notes 生命周期

- 重点：
  - active / resolved / archived 的推进规则
  - 章节收束时的 note 归档
  - 与 compaction、retrieval、context builder 贯通

## P3：中期探索

### 任务 7：推进下一层安全输出接口

- 前提：
  - 主链减压完成
  - mock/后端语义一致
  - reviewed apply 结构稳定

### 任务 8：评估多角色协作与更强知识检索

- 前提：
  - 当前 `Director + WorldCurator + NpcIntent` 路径稳定
  - 记忆与 protocol 层已具备明确接入点

## 3. 不建议现在就做的事

- 直接让 `NoName` 改写最终剧情状态
- 继续把复杂逻辑堆进 `tauri_commands.rs`
- 基于旧卡片继续发“未开始”任务而不核对当前代码

## 4. 两周建议排期

### 第 1 周

- 修复测试污染
- 对齐 `webRuntime`
- 清理 `tauri_commands.rs` 中最明显的 `NoName` 编排重复

### 第 2 周

- 推进 retrieval 与 structured notes 的串联
- 补充相应测试
- 评估下一层受控输出是否具备试点条件

更细的分工、交接目标、红线与文档要求，见 [未来两周开发排期](./04-未来两周开发排期.md)。
