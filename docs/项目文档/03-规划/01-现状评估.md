# 现状评估

## 1. 总体判断

当前 `Nobody` 的代码状态是“主游戏引擎稳定、`NoName` 进入受控增强深化阶段、但工程层需要收口”。

这不是一个需要“推倒重来”的项目，而是一个需要“继续收敛主链复杂度”的项目。

## 2. 主要优点

- 游戏主循环已完整
- Rust 后端已形成明确的状态与规则中心
- `NoName` 的 runtime、trace、guardrail、memory、reviewed apply 已经具备可验证闭环
- 前端调试入口已具备，便于持续验证
- 记忆检索排序解释性已完成第一轮增强，结果可说明 `relevance / recency / importance / role_boost` 的排序依据
- Structured Notes 生命周期已完成第一轮收口，`active / resolved / archived` 的合法流转集中到可复用规则
- 角色上下文差异度已完成第一轮增强，`source_stats` 与 `visible_constraints` 能显示角色级上下文偏好
- 检索与 notes 已完成第一轮串联，active notes 可作为检索上下文桥帮助召回相关记忆，archived notes 不参与扩展召回
- 调试台信息结构已完成第一轮优化，trace 面板提供前置快读条，复制摘要提供 `Trace Breakdown`
- reviewed apply 生命周期展示已完成第一轮收口，前端可核对 `Human Review -> Second Guardrail -> Manual Apply`
- 下一层安全输出接口已完成第一轮试点评估，并已有只读 `NoNameSafeOutputDraft` 探针，当前结论仍是只适合先探索非最终状态的 pending / draft / diagnostics-like 输出层

## 3. 当前主要风险

### 3.1 命令主链压力仍需继续收口

`tauri_commands.rs` 仍然承担大量主游戏编排工作，继续向里面叠逻辑会提高维护风险和冲突概率。

当前 `NoName reviewed apply` 链路已经完成第五轮减压：

- reviewed apply request 构造、快照校验与显式 apply 已下沉到 `noname_apply.rs`
- trace 获取 / plot state 更新 / trace 回写已复用命令层共用壳层
- human review intent、人工复核结果写回与 second guardrail 预校验 / 决策记录已下沉到 `noname_apply.rs`
- `apply_noname_reviewed_output` 的 request input 组装也已回收到 `noname_apply.rs`

因此 A2/A3 在当前主开发线可以视为阶段性完成。后续风险重点不再是 reviewed apply 本身，而是其他低风险 apply 与剧情生成主链是否继续膨胀。

### 3.2 前后端 mock 语义漂移

如果 `webRuntime.ts` 不跟随真实后端更新，前端测试和调试会逐渐偏离生产行为。

当前这一风险已经完成第一轮收口：

- Web mock 的 `policyForbiddenScopes` 已补齐到与后端一致的默认禁区集合
- review 到 proposal 的绑定不再走模糊匹配

但后续只要后端 review / apply 语义继续演化，Web mock 仍需同步维护。

### 3.3 文档状态漂移

旧文档里存在大量“已实现能力被写成未开始”的情况，已经不能继续作为正式项目基线。

### 3.4 验证环境污染

这一风险已经完成第一轮收口：Vitest 的前端测试发现范围已收紧到 `src/`，并显式排除了 `.review/`。
当前仍需注意的是：如果后续新增前端测试目录，必须同步更新 `vitest.config.ts`，否则测试发现范围会再次漂移。

### 3.5 记忆检索与 notes 串联仍未完成

检索排序解释性、notes 生命周期和 notes/retrieval 串联第一轮已经具备；note-aware retrieval 已接入 context builder，使 active notes 扩展出的召回结果能够进入角色上下文包。章节 compaction 输入的第一轮收口也已完成：当前章节 episodic events、非 `archived` notes 会进入章节压缩，而旧的 `compact-chapter-*` summary 已被排除，避免重复压缩时发生 summary 回吃。章节收束顺序也已在 `NoNameMemoryManager` 固定为“先 compact，再 archive resolved notes，最后写回 chapter summary”，避免 resolved note 丢出摘要，也避免新 summary 污染同轮 note review。当前剩余缺口主要在更高层 runtime 编排的贯通，后续需要继续验证 notes 如何稳定参与长期记忆沉淀，而不是只参与单次上下文构建。

### 3.6 下一层安全输出仍不能扩大权限边界

下一层输出接口目前只完成试点评估与只读探针，不代表可以直接写最终剧情状态。当前 `NoNameSafeOutputDraft` 只从 trace 证据推导 `drafted / reviewed / guardrailAllowed / manuallyApplied / blocked / fallback`，并固定 `finalPlotStateWriteAllowed=false`。后续若实现 `draft / pending hint` 类输出，仍必须保留人工复核、二次护栏、显式写入和 stale snapshot 校验。

## 4. 当前最合理的发展策略

先收口，再扩张。

具体来说：

1. 先修工程一致性问题
2. 再抽离主链高耦合逻辑
3. 再增强检索与 notes 质量
4. 最后才考虑更高权重的剧情受控应用

## 5. 结论

当前最不缺的是“新点子”，最缺的是“让现有能力以更稳的方式继续演进”。  
因此后续开发方向应以稳定性、边界清晰和协作可持续为先。
