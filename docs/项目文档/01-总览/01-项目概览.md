# 项目概览

## 1. 项目定位

`Nobody` 是一个以修仙题材为背景的文字模拟器，核心目标不是单纯“让模型写剧情”，而是用一套可控的游戏引擎来推进剧情、状态和世界演化。

项目当前的真实定位可以概括为：

- 前端提供游戏交互、信息中心、调试与配置能力
- Rust 后端维护剧情状态、世界状态、规则校验和存档
- `NoName` 为引擎提供受控的 Agent 增强能力，但不能绕过主状态机直接改世界

## 2. 核心组成

### 前端

- 技术栈：`Vue 3 + TypeScript + Pinia + Tailwind CSS`
- 主要职责：
  - 主游戏界面与交互
  - 信息中心、系统中心、调试台
  - `NoName` trace 与人工 review 操作入口

### 后端

- 技术栈：`Tauri 2 + Rust`
- 主要职责：
  - 剧情推进
  - 世界状态维护
  - 一致性与护栏检查
  - 存档与脚本加载
  - `NoName` runtime、trace、memory、guardrail

## 3. 仓库结构

```text
src/                    前端页面、组件、状态与 Web mock
src-tauri/src/          Rust 后端核心引擎与 NoName 子系统
docs/项目文档/          当前正式中文文档
.kiro/                  历史规格、草稿、handoff 与归档资料
release/                发布相关辅助资料
example_scripts/        示例剧本与脚本资料
```

## 4. 当前阶段

项目整体处在“`V2` 游戏引擎稳定化 + `NoName V1/T7` 继续收口”的阶段：

- 基础游戏闭环已经完整
- `NoName` 已经接入 runtime、trace、memory、role context、受控输出 review、debug console
- 更高风险的剧情正文控制能力仍应谨慎推进

## 5. 当前最重要的判断

- `Nobody` 的单一事实源仍然是后端状态与规则系统
- `NoName` 的价值是增强，而不是替代引擎
- 当前开发重点应从“继续加模块”转向“统一语义、降低耦合、稳定协作边界”
